# 学生端页面布局优化设计

## 背景

当前学生端是 Streamlit 多页应用中的 4 步诊断向导，页面顺序为：顶部 Hero、操作步骤说明卡、当前步骤提示、当前步骤表单、底部导航按钮、诊断结果区。诊断逻辑、图片暂存、数据库保存、复盘报告导出都已经集中在现有函数中，本次优化只调整学生端页面布局与视觉层级。

## 目标

采用“聚焦式向导”布局，让学生在课堂演示中更容易判断当前要做什么。页面应减少重复说明，突出当前步骤、当前输入项和下一步动作，同时保留原有 4 步流程与所有业务行为。

## 非目标

本次不修改诊断规则、评分逻辑、AI 文本线索抽取、数据库结构、图片保存逻辑、教师端页面或开发调试端页面。不新增依赖，不引入新的前端框架。

## 推荐方案

选择 A：聚焦式向导。

页面结构调整为：

1. 顶部 Hero：保留学生端标题和说明文案，整体高度略收敛。
2. 轻量步骤条：替代当前占空间较大的“操作步骤”四卡片，展示 4 个步骤、当前步骤高亮、已完成步骤状态。
3. 当前步骤面板：只展示当前步骤的表单内容，标题和说明更紧凑。
4. 底部导航区：保留“上一步 / 下一步 / 开始诊断”，让主要操作更靠近表单。
5. 诊断结果区：诊断后显示在向导下方，保留 Top1 高亮、Top2/Top3 候选、诊断依据展开和复盘报告导出。

## 组件设计

### 学生端页面

主要改动文件为 `pages/1_学生端.py`。

- 保留现有 `STUDENT_STEP_TITLES`、表单默认值、演示数据、session 持久化和诊断执行函数。
- 改造 `render_student_wizard_header()`，让它承担轻量步骤导航职责。
- 移除或压缩 `main()` 中“操作步骤”大卡片区域，避免 Hero 下方出现过多说明内容。
- 将“加载演示数据”放入轻量操作区，保留课堂演示入口。
- 保留 4 个 `render_step_*` 函数的业务输入字段，只优化标题、说明、列布局和提示文案密度。

### 通用样式

主要改动文件为 `core.py`。

- 在 `apply_common_styles(theme="student")` 中补充学生端向导所需 CSS 类。
- 新增或强化步骤条、当前步骤状态、表单面板、按钮区的视觉样式。
- 保持中文 UI 风格，不改变教师端和开发调试端已有布局。

## 数据流

数据流保持不变：

1. 用户在各步骤输入内容。
2. `sync_val()` 将组件值同步到 `student_data_storage`。
3. 步骤切换只改变 `student_current_step`。
4. 最后一步调用 `run_student_diagnosis()`。
5. 诊断结果写入 `student_last_payload`，并保存到 SQLite。
6. 结果区根据 `student_last_payload` 渲染。

## 错误处理

沿用现有错误处理：

- 图片保存失败时显示 warning，不阻断诊断。
- 无图片时显示提示。
- 规则缺失时显示 warning。
- 诊断结果保存成功时显示成功提示。

布局优化不新增新的错误状态。

## 响应式策略

桌面端优先保证课堂投屏时的信息层级清晰。步骤条横向展示，当前表单使用两列输入。窄屏下保留 Streamlit 默认列堆叠能力，并通过 CSS 减少卡片间距和标题尺寸，避免文字拥挤。

## 验证计划

项目没有自动化测试、lint 或构建步骤。实现后进行以下验证：

1. 运行 Python 语法检查，确认改动文件无语法错误。
2. 启动 `streamlit run app.py`，确认应用可启动。
3. 手动走通学生端 4 步：加载演示数据、切换步骤、上传或不上传图片、开始诊断。
4. 确认诊断结果、依据展开、复盘报告生成与下载入口仍可用。

## 自检结论

本设计聚焦学生端布局优化，范围清晰，不涉及诊断业务逻辑。方案与现有 Streamlit 架构兼容，主要通过渲染函数和 CSS 调整完成，适合在不引入新依赖的前提下改进课堂演示体验。
