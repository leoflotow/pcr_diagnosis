# 电泳图 AI 辅助识别升级方案

产品：生物实验智学助手
副标题：面向本科生物实验教学的知识探索与智能复盘工具
当前模块：电泳异常分析；实验专题：PCR 与电泳
方案日期：2026-10-04；状态：已按用户确认实现首版，文字和图片统一为 DeepSeek `deepseek-flash`。使用步骤见同目录《电泳图AI辅助观察使用说明》。

## 1. 推荐方案与边界

新增独立的“电泳图 AI 辅助观察”面板。首版只生成待核对的图像观察，帮助师生检查泳道和条带；AI 原始结果与人工核对记录均不自动进入现有规则引擎，不增加诊断分数，不自动覆盖实验现象、对照结果、教师结论或学习评价。

学生仍按现有流程记录实验、独立初判、生成规则建议、补证、等待教师复核、修订与制定验证计划。若观察图像后需要修改现有实验观察，学生使用原有表单或补证入口自行填写，程序仍按现有规则处理。教师最终原因仍由教师结合原始图像与实验记录确认。

保持现有产品名称、导航、四步输入向导、规则库、原因排序、证据支持程度、账号验证、课堂统计、SQLite 和 Python/Streamlit 架构。页面不出现比赛、演示、demo 或虚拟数据用途说明。没有图片、不启用识别、接口不可用时，全部原有功能照常使用。

## 2. 已落实的模型配置

方案日期保留为 2026-10-04，本文于 2026-10-08 按代码复核。文字抽取、追问润色、操作线索与图像观察均由 `ai_config.py` 固定使用 DeepSeek 官方 `https://api.deepseek.com` 和 `deepseek-flash`，共用 `DEEPSEEK_API_KEY`。未接入千问、智谱、GPT 或 Claude，也不设置其他模型自动兜底；旧 `BIGMODEL_*`、自定义模型名与地址不用于请求。

用户已在本地配置密钥；此前用匿名固定文本和程序生成图片完成在线联调，不需要再开通第二个视觉服务。密钥仅由程序读取，不在页面或文档中展示。请求记录保存返回模型标识、提示词版本及 Token 用量；模型别名不代表永久冻结的服务快照。`openai` Python 包仅为兼容客户端。

## 3. 页面与操作路径

1. 学生第 3 步照常上传 PNG/JPG 并填写人工泳道说明，文件上限保持 10 MB。
2. 第 4 步先提交独立初判，按原流程生成规则结果。AI 观察面板放在结果页原有凝胶图区域，避免学生的独立初判先受到 AI 提示影响。
3. 学生手动指定图中泳道与 Marker、阳性、阴性、样本的对应关系，可保留“身份未确认”。角色不由 AI 自动决定。预期片段沿用原有输入，未填则保持未知。
4. 点击“AI 辅助观察”才发送请求。上传、切换步骤、页面重绘和刷新反馈均不自动触发。
5. 显示原始图像、处理后的发送预览和待核对观察表。首版不生成泳道或条带定位框，也不返回像素坐标。
6. 每项初始为“未核对”，学生可选择“与原图一致”“已修正”“无法确认”，并保存修正后的观察。没有默认勾选，也不提供一键全部接受。
7. 教师在原案例详情看到原图、AI 原始候选、学生核对及修正记录，保存图像观察复核意见；原来的原因确认表单和反馈版本机制保持不变。

建议页面文案：

> 电泳图 AI 辅助观察
> AI 结果可能出现漏识别或误识别，请逐项对照原图核对；系统不会将其直接作为诊断依据。

按钮：“AI 辅助观察”“保存核对记录”。失败提示：“本次辅助识别未完成，可继续人工观察与实验复盘。”

识别按钮附近简洁说明图像将发送至配置的国内模型服务。允许选择不使用；不把云端调用误描述为本地识别。

## 4. 首版输出范围

| 观察项目 | 允许的输出 | 限制 |
| --- | --- | --- |
| 图像可读性 | 可辨、部分可辨、无法判读及对应原因 | 质量判断也需核对，不是准确率 |
| 泳道对应 | 人工映射中的泳道编号 | 不输出定位框或坐标；身份以人工关系为准 |
| 离散条带 | 可见候选数量、位置 | 看不清时为未知，不能默认填 0 |
| 图像现象 | 未见清晰条带、单条、多个、弥散/拖尾、无法确认 | 描述可见现象，不等于实验原因 |
| 相对位置与亮度 | 靠近加样孔、中部、远离加样孔、多个位置或无法确认；较亮、较弱或无法确认 | 不输出定量比较、bp、DNA 浓度或产量 |
| 需核对处 | 背景亮、边缘缺失、局部过曝、弱带不清、泳道对应关系不明 | 允许拒绝继续判读 |

首版不输出污染、模板不足、引物问题、酶失活或退火温度异常等原因；不输出实验成功与否、诊断排名、评分或准确率。缺少可靠 Marker 信息时不估计片段大小。精确 bp 标定与灰度定量不纳入此次范围。

NEB 的排错资料将同一现象对应到多个可能原因，阴性泳道的异常也可能涉及引物产物。因此“图像观察→实验原因”不能由通用视觉模型直接跨越。

## 5. 防误用设计

- 图像识别模块只返回观察白名单，没有诊断或评分函数权限。多余的原因字段直接拒收，不能写入已有 `confirmed_hints`、对照结果或原因字段。
- 输出采用受限 JSON，验证字段、枚举、泳道编号、数量及数量与形态的一致性。语法正确只能证明格式合法，不能证明内容真实。
- 未提供泳道身份时，不猜阳性或阴性。未知字段明确保留为空或“无法确认”。不显示模型自报的“98% 置信度”等数值。
- 原始结果、学生核对、教师复核分别保存，人工修改不覆盖原始模型响应。图像观察的复核版本独立于已有教师原因反馈版本。
- 图片、裁剪、方向或泳道关系改变时，旧结果标为对应旧版本，不继续用于当前图片；重新识别仍需主动点击。模型或提示词升级不自动重识别历史案例。
- 图中文字只作为图像标签处理，不作为可执行指令；不启用工具调用、联网搜索或自主代理。
- 不设自动多模型投票，也不把学生与模型的一致视为真实识别正确率。

## 6. 最小实施范围

新增 `gel_image_assistant.py`：图像调用、受限响应解析、指纹和结果状态。复用现有 OpenAI 兼容客户端，把文字请求中的纯字符串改为图像请求所需的文字与图片内容块；图像提示词与文字线索抽取提示词分别管理。使用现有 Pillow 生成发送副本，保留原图；可去除 EXIF、处理方向并只发送凝胶区域，不过度压缩弱条带细节。DeepSeek 官方文档说明服务内部仍会调整图片尺寸，因此即使采用原始细节模式，也不能保证细弱条带完整保留，须结合实际图片核验。

在 `pages/1_学生端.py` 的结果图像区域添加按需识别和核对组件；在 `pages/2_教师端.py` 的原案例详情添加图像观察复核组件。第 3 步“系统不自动判读凝胶图”说明相应改成按需辅助观察的说明。

`case_storage.py` 已增加 `gel_observation_runs` 与 `gel_observation_checks` 两张表：前者保存案例 ID、图片指纹、发送设置、泳道映射、模型与提示词版本、状态、Token 和原始候选；后者分别追加学生核对与教师复核，并记录教师对应的学生核对版本。均不重写历史诊断。

`core.py` 仅增补存取接口与报告中的可选“图像辅助观察与人工核对”部分，不修改 `diagnose()`、规则分值、归一化原因或教师结论逻辑。未经核对的候选始终注明“未核对”，不与人工观察混排为事实。

开发端显示图像功能启用状态、密钥是否配置、固定模型、最近请求状态与 Token，不显示或编辑 API Key，也没有完整费用账单。开关通过环境或 secrets 的 `DEEPSEEK_VISION_ENABLED` 设置。沿用当前中文视觉样式，完成后以真实浏览器截图和尺寸检查验收。

## 7. 请求、隐私与费用

首版沿用现有本地 Python 后台，调用国内视觉 API，无需为这一个功能另租 GPU 服务器。API 图片传输与模型计费是新增成本；未配置时功能关闭。按案例、图像、泳道关系、提示词及模型版本缓存，避免 Streamlit 重绘重复请求，不跨用户共享私人图片结果。

只发送必要凝胶区域与匿名泳道信息，不发送学生姓名、班级名单、完整案例历史或查询码。带身份标签的照片先由使用者裁剪或遮盖；原图本地保留，处理副本与原图分别记录。采用 Base64 请求可避免把学生图片挂到公开 URL，但仍属于向服务商发送图片，不保证供应商零留存。

首版图片请求固定 30 秒超时，无自动重试，限制输出长度。30 秒是工程预算而非性能承诺；失败可手动重试，不切换境外服务。

图像与文字均产生实际接口用量，复用账号不等于免费。本文不把 2026-10-04 的报价当作当前价格；费用请按 DeepSeek 官方价格页及账号账单核对。输入/输出长度、缓存与图像处理会影响用量，功能测试 Token 不能推算本班全部费用。

首版开发端显示最近图像请求状态与接口返回的 Token；实际费用按 DeepSeek 账号账单核对。管理员可通过 `DEEPSEEK_VISION_ENABLED=false` 暂停图像调用，不影响原有课堂流程。首版未实现按货币金额自动停止请求，不能把 Token 记录当作完整账单。

## 8. 实施顺序与验收

1. 已固定观察字段、泳道映射和人工核对状态，接通 DeepSeek 官方服务。
2. 已添加学生与教师面板、图片版本失效处理及独立存储。
3. 已用临时库测试图像模块、报告与既有流程，保留实际课堂数据库和照片。
4. 待教师提供脱敏图作实图核验；覆盖清楚、弱带、多带、拖尾、过曝、低分辨率、裁剪、反向、缺 Marker 等情况。建议起步 20–30 张，不以此小样本直接宣称教学效果或普适准确率；同一原图及其变体不能分散到校准集和独立验收集。
5. 待记录模型响应标识并固定提示词后，用独立图片评估条带误增、漏检、泳道错配、正确保留未知的比例，以及教师需要修正的工作量。人工参考标注存在争议时保留“有争议”，不强设标准答案。

功能硬性验收：

- 未核对或被拒收的 AI 输出对诊断候选、分数、教师原因和学生成绩产生零影响。
- 在既有表单输入不变的情况下，启用识别、保存核对或拒绝候选均不改变原规则结果；不把 AI 内容偷偷送进原来的文本抽取。
- 人工更正、未知观察、断网、限流、余额不足、超时、损坏图片和 JSON 异常均可继续原流程。
- 更换图片后，旧候选和核对状态不能套用到新图；已存历史图像版本及诊断快照不被覆盖。
- 2026-10-08 共 51 项单元测试通过；此前有图/无图完整流程已通过，新增断言核验图像候选隔离。
- 手机与桌面原图/核对表可用；正式页面不增加比赛用途或演示说明。
